# 《陪析》产品设计稿 v1.0（最终版）

## 一、已锁定的核心决策（不可更改的前提）

| 决策项 | 结论 |
|---|---|
| 目标平台 | Windows EXE + Android APK，**Flutter 一套代码** |
| 视频来源 | 仅本地文件（mp4/mkv/avi 等） |

### 2.3 关键外部服务

1. **OSS 中转桶**（用户自建，免费额度足够）：ASR 接口需要公网可访问的音频 URL，因此流程为：客户端压缩音频 → 上传 OSS（私有读）→ 生成限时签名 URL 给 ASR → 识别完成后自动删除对象。
2. **DashScope 录音文件识别**：提交任务 → 轮询结果。期望参数（⚠️ 实现前务必对照最新官方文档核对）：`model=paraformer-v2`、`diarization_enabled=true`、`language_hints=["zh"]`，返回每句的 `begin_time / end_time / text / speaker_id`。
3. **LLM（OpenAI 兼容）**：默认预设 `base_url=https://dashscope.aliyuncs.com/compatible-mode/v1`，默认模型 `qwen-plus`；廉价任务用 `qwen-flash`。设置页允许任意自定义。

> ⚠️ **实现前核对清单**（程序员第一步）：① paraformer-v2 的说话人分离参数名与返回字段；② compatible-mode 地址与是否支持 response_format=json_object；③ 百炼各模型免费额度现状；④ OSS 签名 URL 的生成方式。核对结果写入交付说明。

## 四、视频处理流水线（项目状态机，每阶段落盘可断点续跑）

**S1 导入探测**：file_picker 选文件 → ffmpeg 读取时长/封装信息 → 从文件名启发式解析剧名与集数（如 `潜伏 S01E03`）→ 建 project 记录。

**S2 字幕提取尝试（可选加速）**：若容器内嵌字幕流（srt/mov_text），ffmpeg 提取为文本。用途：① 与 ASR 结果交叉校对错别字；② 字幕有时自带角色名，可直接提升映射准确率。提取失败则跳过，不阻塞。

**S3 音频抽取压缩**：ffmpeg 转 **16kHz 单声道 MP3（约 48–64kbps）**。一集 45 分钟约 20MB，控制上传体积。产出临时音频文件供全流程复用（校准页试听也用它）。

**S4 上传 OSS**：dio 分片上传（显示进度条）→ 对象设私有 → 生成长时效（如 24h）签名 GET URL。

**S5 ASR 任务**：提交转录任务 → 每 5 秒轮询，超时上限 30 分钟 → 下载结果 JSON → 解析为上面的规范化结构 → **删除 OSS 对象**。App 被杀后重启可凭持久化的 task_id 续轮询。

**S6 角色自动映射（LLM）**：调用 Prompt A（见第七节），输入全量对白+文件名，得到 `characters` 表初始数据。置信度 < 0.6 的标记待校准。

**S7 人工校准闸门**：状态置 `WAIT_CALIBRATION`，进入播放器前强制经过校准页（详见 8.3）。用户确认/修正后置 `CALIBRATED`。**此闸门必须在解说生成之前**，保证下游使用最终名字。

**S8 场景切分（纯本地算法）**：规则——相邻对白间隔 > 3 秒即切开；单场景超 120 秒强制切；不足 15 秒并入邻景。产出 scenes 表。

**S9 逐段解说生成（防剧透核心）**：按场景顺序循环调用 Prompt B，每次上下文 = 【前情滚动摘要（Prompt E 维护，≤300字）+ 当前场景全部对白】，**严禁传入任何后续内容**。每完成一个场景立即写库（崩溃可续跑）。同时：对返回的 `knowledge_needed` 词条查重后调用 Prompt C 生成知识卡片；`l4_question` 写入 questions 表。限速：串行调用 + 失败指数退避重试 3 次。

**S10 完成**：状态 `READY`，清理临时音频（保留与否由设置决定，默认保留供校准回访）。

## 五、小说处理流水线

**N1 导入**：编码检测（UTF-8 严格解码失败→GB18030）→ 统一换行符 → 按 `第X章/回/卷` 正则切章（匹配不到则按每 ~2000 字符在段落边界切块）→ 建 chapters/paragraphs。

**N2 人物提取**：每章调用一次轻量 LLM，汇总维护全书人物名单与一句话人设（随进度更新），保证批注指代一致。

**N3 批注生成（同样顺序防剧透）**：按章内段落块（每次 ~2000 字）顺序调用 Prompt D，上下文 = 前文章节摘要 + 本章已读部分概要 + 当前块全文。批注锚定段落 idx，类型 L1/L2/L3/L4。L4 以**段间插入式问题卡片**呈现（阅读场景不适用弹幕打断，改为卡片展开作答）。

**N4 完成**：进入阅读器。

## 六、LLM 接入层规范

1. **唯一出口**：`LlmService.chat(messages, {tier, jsonMode})`，底层为 OpenAI `/chat/completions` 兼容协议。禁止业务代码直连具体厂商 SDK。
2. **模型分层**：`cheap`（映射/摘要/人物提取→qwen-flash）、`standard`（解说/批注/知识卡→qwen-plus）。设置页可分别覆盖模型名。
3. **JSON 稳健性**：jsonMode 优先；解析失败时执行兜底链——剥 markdown 围栏 → 正则截取首尾大括号 → 将原文+报错回传 LLM 要求修复（最多 1 次）→ 仍失败则标记该场景失败并继续下一个。
4. **缓存**：所有 LLM 结果落库，key = hash(提示词版本+输入内容)，重复处理零消耗。
5. **成本面板**：llm_logs 汇总，设置页展示本项目累计 token 消耗估算。

## 七、Prompt 模板全集（直接实现，可微调措辞勿改结构）

**通用系统前缀**（所有模板附加）：“只输出 JSON，不要 markdown 代码块，不要解释。不确定的信息明确说不确定，严禁编造剧情和设定。”

### Prompt A：角色映射
```
你是影视剧对白分析专家。以下对白中的 SPEAKER_xx 是声纹聚类编号，同一编号=同一真实声音。
任务：推断每个编号对应的剧中角色名。
依据优先级：①人物互相称呼与自称 ②语气风格 ③你对《{title}》这部剧的了解（如有把握）。
无法确定的命名"未知·声音X"，禁止编造。
输出：{"characters":[{"speaker_id":"","name":"","confidence":0.0,"evidence":"判断依据","is_major":false}]}
[文件名]{filename}
[对白]
[SPEAKER_00][00:01:12]……
```

### Prompt B：场景解说（顺序调用，防剧透）
```
你是用户的私人观剧教练，陪用户提升情商与思维。只准使用截至本场景的信息。
[前情摘要]{digest}
[本场景对白]{dialogues_with_names_and_timestamps}
输出：
{"scene_summary":"一句话",
 "importance":"high|normal",
 "l1_subtext":"潜台词解读，80字内，点破话外之音",
 "l2_psychology":[{"character":"","analysis":"动机/性格/情绪，100字内"}],
 "knowledge_needed":["观众可能不懂的名词，无则空数组"],
 "l4_question":{"question":"抛给用户的开放性问题，逼其代入思考","perspectives":["参考角度1","参考角度2","参考角度3"]}}
要求：分析必须引用具体台词；l4 问题要具体到本场景抉择，不要空泛鸡汤。
```

### Prompt C：知识卡片
```
为观剧用户写背景知识卡片，词条「{term}」，语境：{剧名+出现场景一句话}。
要求150-250字：是什么+为什么在此剧语境中重要，通俗准确。
若对该词条无把握，输出 {"title":"{term}","content":"","uncertain":true}。
```

### Prompt E：滚动摘要
```
将旧摘要与新场景信息合并为不超过300字的前情摘要，必须保留：人物关系、立场悬念、未回收伏笔。
[旧摘要]{digest}[新场景]{scene_summary+l1}
```

### Prompt D：小说批注（结构同 B，锚定改为 `"para_range":[起,止]`，增加指令："批注密度：平均每屏(约5段)1-2条，只在有分析价值的段落标注，宁缺毋滥。”）

## 八、UI 规格

### 8.1 媒体库（首页）
项目卡片网格：封面色块+标题+类型图标+状态徽章（处理中显示阶段进度条，如“语音识别 65%”）。悬浮/长按：删除（二次确认，连带删产物）、导出。

### 8.2 视频播放器页（核心页面）
- **布局**：桌面左视频右解说栏（宽 ≥360px 可折叠）；手机竖屏上视频下解说卡，横屏同桌面。
- **解说卡切换**：监听播放位置 → 二分查找当前场景 → 场景变化时旧卡淡出下滑、新卡淡入上滑（动画 250ms）。卡内分区：`L1 潜台词`（常显）→ `L2 心理`（折叠，按角色分条）→ `L3 知识`（词条胶囊按钮，点击弹出底部卡片，看过的卡片进“卡片集”）。
- **进度条**：下方刻度点标记场景边界，橙色点=含 L4 提问的场景，可点击跳转。
- **弹幕提问打断流程（L4，默认开启）**：播放进入含 high 重要度问题的场景 30% 处触发（受频率限制：默认每集最多 5 次、两次间隔 ≥4 分钟）→ **自动暂停** → 全屏模组卡：问题 + 多行输入框 + 按钮〔跳过本题〕〔提交回答〕→ 提交后展示 perspectives 参考视角 + 〔继续播放〕→ 写 qa_records。跳过也记录（skipped=true）。
- **暂停深读**：手动暂停时解说卡自动展开全部层级。

### 8.3 校准页（S7 闸门）
按台词量降序列出声音簇。每簇一行：色块 + 最长 3 句代表台词 + ▶试听（播放对应时间段音频）+ 建议名胶囊（取 LLM 低置信度候选）+ 自定义输入框。顶部提供〔全部采纳建议〕快捷键。确认后进入处理剩余阶段。

### 8.4 小说阅读器
- 正文纵向滚动，字号/行距/背景色（含夜间）可调。
- 批注呈现：段落尾部小气泡角标（颜色区分 L1-L4），点击底部弹层显示内容；L4 为段间展开卡片，作答交互同 8.2。
- 顶部章节抽屉；右上入口：本章人物列表（点击看人设）。

### 8.5 卡片集 / 复盘页
- 卡片集：全部知识卡片按剧分组浏览，搜索。
- 复盘页：qa_records 时间线列表（我的回答 vs 参考视角），统计：已答/跳过数、连续答题天数。

### 8.6 设置页
- **API 配置**：供应商预设下拉（默认“阿里云百炼”，自动填 base_url）＋〔自定义〕展开 base_url/api_key/model(cheap)/model(standard) 四个输入框；〔测试连接〕按钮发一条最小请求验证。
- OSS 配置：bucket/endpoint/AK/SK（存 secure_storage）。
- 播放偏好：弹幕提问总开关、每集上限、最小间隔、触发位置比例。
- 数据：临时音频保留开关、导出/导入项目包（zip：SQLite 行 JSON + 元信息，M3 实现）。

## 九、非功能需求

1. **容错**：流水线任一阶段失败 → 状态 FAILED+failed_stage，媒体库卡片上给出〔重试该阶段〕按钮；网络类错误自动退避重试。
2. **性能**：45 分钟剧集全流程目标 ≤15 分钟（视 ASR 排队）；播放器拖动进度条时解说切换不得掉帧（查找用索引，渲染用懒加载）。
3. **隐私**：API Key/OSS 密钥仅存本地安全存储；OSS 对象用后即删；不上传任何数据到开发者服务器（本项目无自有服务器）。
4. **Android 特殊处理**：处理期间页面保持唤醒（wakelock），页面顶部明示“处理中请勿关闭”；SAF 权限持久化。
5. **成本预期**：单集 LLM 消耗约 5 万 token 量级，百炼免费额度可覆盖大量使用；ASR 按时长计费（约每小时几毛钱级别，以官网为准）。

## 十、里程碑与验收标准

**M1 视频主链路（先 Windows 后 Android）**
验收：导入一个 45 分钟国产剧 mkv → 自动完成 S1-S10 → 播放时解说卡随剧情正确切换、角色名正确率经一次校准后目测 ≥90%、知识卡至少命中 1 个谍战名词、断网中断后可续跑。

**M2 弹幕提问 + 小说模式**
验收：L4 打断-作答-复盘闭环可用且频率限制生效；GBK 编码 TXT 正常导入分章，批注气泡定位准确。

**M3 打磨**
卡片集、复盘统计、项目包导出导入、EPUB 支持（epubx）、实验性视觉辅助（抽关键帧交 qwen-vl 判断“谁在说话”，用于降低校准率）。

## 十一、风险与备选方案

| 风险 | 缓解/Plan B |
|---|---|
| DashScope ASR 要求公网 URL 流程受阻 | Plan B：本地集成 sherpa-onnx 离线 ASR+声纹（Paraformer/CAM++ ONNX 模型，CPU 可跑，速度慢精度略低但零上传） |
| 强 BGM 导致识别/分离质量差 | MVP 不做本地人声分离（手机算力不够）；依赖 paraformer 抗噪能力；效果不佳时在 Windows 端提供可选 Demucs 预处理开关 |
| LLM 幻觉编造剧情 | 所有模板已强约束；知识卡 uncertain 机制；复盘页可标记错误卡片 |
| 跨集角色声纹不互通（云 ASR 不返回声纹向量） | 每集独立校准（成本低）；V2 可用 sherpa 声纹做同剧跨集自动匹配 |
