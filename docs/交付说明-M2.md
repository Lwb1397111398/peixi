# 交付说明 · M2（小说模式 N1-N4 + 阅读器 + 本地 ASR 双模式）

> 代码基线：M1 完整版之上增量。本阶段新增测试 45 个，全套 **110 个测试全绿**（`flutter test`），`flutter analyze` 无告警。

## 一、交付范围

### 小说线（A1-A5）
| 任务 | 交付物 |
|---|---|
| A1 编码检测+切章 | `lib/core/novel/novel_parser.dart`：UTF-8 严格解码失败→GBK（gbk_codec，永不抛异常）；CRLF/BOM 归一；`第X章/回/卷/节` 与 楔子/序章/引子/尾声/终章/番外 标题切章（标题行 ≤40 字防误切，含全角空格清洗）；无标题按 ~2000 字段落边界分块（尾块过小并入前块） |
| A2 导入入库 | `novel_importer.dart`（NovelImporter/NovelMeta）：projects(type='novel')+chapters+paragraphs 一个事务；paragraphs.idx 为全书全局序号（批注锚定基准）；Android 下 txt 复制进应用目录（同视频策略） |
| A2 人物提取 | `novel_pipeline.dart`（NovelCharacterExtractor）：逐章 cheap 调用，滚动维护全书名单+一句话人设，同时产出 60 字章摘要（存 chapters.summary，N3 前情复用）；按名字去重合并、人设可更新；已有摘要的章跳过（续跑幂等） |
| A2/A3 状态机 | `NovelPipelineEngine`：IMPORTED→(N2 map)→MAPPED→(N3 commentary)→COMMENTARY_DONE→(N4 finalize)→READY；FAILED+failed_stage 语义与视频引擎一致；`novelEntryStatusOfStage` 负责失败回退 |
| A3 批注生成 | `novel_commentary_generator.dart` + Prompt D（`Prompts.novelAnnotation`）：按章内 ~2000 字块**全局顺序**调用（防剧透）；上下文=前情滚动摘要(Prompt E, cheap)+本章已读块概要+当前块；批注锚定 para_idx、类型 L1-L4 写 `annotations`；每块与断点（meta_json.annotated_para）**同事务落库**（崩溃续跑）；摘要调用失败降级拼接不阻塞主线 |
| A4 阅读器 | `lib/features/reader/reader_page.dart` + `reader.dart`：段落尾部 L1-L4 彩色气泡角标（蓝/紫/绿/橙）→底部弹层；L4 段间卡片（作答/跳过→Questions+QaRecords，跳过也记录）；章节抽屉（当前章高亮）；本书人物列表（含人设）；字号/行距/背景（纸白/米黄/夜间）实时可调并存 settings 表 |
| A5 媒体库 | 导入小说按钮（与导入视频并列）；卡片点击按 type 路由：novel READY→阅读器、video READY→播放器；小说状态文案（人物提取/批注生成等） |

## 二、偏离与实现决策（相对设计稿）

1. **N2 Prompt 自拟**：设计稿只描述行为未给模板。`Prompts.novelCast` 顺带产出章摘要——N3 的"前文章节摘要"上下文由此获得，省一整轮 LLM 调用。
2. **Prompt D 输出结构**：设计稿"结构同 B"，但阅读器需要"按段落锚定的多类型批注"，故输出为 `annotations:[{para_idx,type,content}]`；L1/L2 content 为字符串，L3/L4 为对象。越界/空名/未知类型的锚点直接丢弃。
3. **L3 知识卡合并生成**：视频是 knowledge_needed→Prompt C 二次调用；小说场景 Prompt D 直接给出 L3 内容（减少一半调用），同时写入 `knowledge_cards`（按 projectId+term 去重）供 M3 卡片集。
4. **人物人设存储**：novel 项目把"一句话人设"存 `characters.aliases_json`（视频项目该列仍是说话人别名语义）。不加列、不动 schema。
5. **小说状态复用视频枚举**：N2→MAPPED、N3→COMMENTARY_DONE、N4→READY；UPLOAD/ASR/校准/场景切分等状态对 novel 永不出现。续跑按 `type` 分流到对应引擎。
6. **阅读器 L4 作答**：每次作答/跳过新建 Questions 行 + QaRecords（不复用视频弹幕问题的行），复盘页按时间线展示。
7. **本地切句策略**：paraformer-zh-2024-03-09 输出无标点时按 token 间静音间隙（>0.6s）切句，间隙不可靠时有 30 token 上限兜底。
8. **小说进度徽章**：`处理中` 无细粒度进度条的阶段（人物提取/批注生成）用事件 progress 回调驱动（done/total）。

## 三、已知限制

- **本地 ASR 无说话人分离**：所有句子 speaker=SPEAKER_00；校准页退化为单一说话人（设计稿风险表 Plan B 已列，交付说明如实注明）。云端模式不受影响。
- **本地精度**：int8 量化 + 单模型，低于云端 paraformer-v2；专有名词/方言场景差距更明显。
- **截词风险**：无 VAD，30s 窗边界虽做低能量吸附，仍可能截断长句；后续可接 silero VAD 优化（sherpa_onnx 自带 vad 模块）。
- **模型需手动下载**（~100-230MB）：未下载时本地模式在 asr 阶段 FAILED，错误信息含下载指引；设置页可查看模型目录与状态。
- **长篇逐章调用**：N2 按设计稿"每章调用一次"，千章书=千次 cheap 调用；个人使用可接受，后续可按字数聚合章再调用。
- **"本章人物"**：展示全书人物列表（未跟踪人物-章节出现关系），点击看人设。
- **模式切换后旧项目**：cloud→local 切换后，已有 mp3 缓存的项目重跑时会自动补转 wav（源视频被清理过则报可读错误）；local→cloud 需重新配置 OSS。

## 四、构建与运行

```bash
flutter pub get                          # 新增依赖：gbk_codec、sherpa_onnx
bash tool/download-sherpa-model.sh       # 本地 ASR 模型（可选，用云端模式可跳过）
flutter build windows                    # / flutter build apk
```

- GitHub 大依赖镜像预取沿用 M1：`tool/fetch-windows-native-deps.sh` / `tool/fetch-android-native-deps.sh`。
- sherpa-onnx 的原生库由 pub 插件自动打包（Windows DLL / Android .so via CMake/Gradle），无需手动放置。
