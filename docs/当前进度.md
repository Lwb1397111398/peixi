# 当前进度

> 最后更新：2026-10-25（会话：Android 接入应用内更新；本日三连做：LLM 渠道化 → APK 打包 → 安卓自更新）

## 当前目标与范围

- 目标：老板装了安卓 APK 后点「检查更新」弹「当前平台暂不支持应用内更新」——因为自更新此前只做了 Windows。本次把 Android 端接入同一条自更新链路：Release 资产按平台区分、下载复用、安装走系统安装器（含「安装未知应用」授权引导）。

## 已验证结果（有证据）

- `flutter analyze` 零问题；`flutter test` **368 个用例全过**（update_test.dart 22→26，新增：安卓按 .apk 挑资产不串 Windows zip、applyUpdate 安卓分支交给安装器不解压不退出、need_permission 提示透传、assetExtensionFor 平台映射）。
- 安卓原生侧：Manifest 声明 `REQUEST_INSTALL_PACKAGES` + FileProvider（authorities `com.jingyue.peixi.fileprovider`，白名单 `res/xml/file_paths.xml` 只放行 `peixi_update/`）；MainActivity.kt 注册 MethodChannel `peixi/app_update`，未授权跳 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 返回 need_permission，已授权 FileProvider 交系统安装器。aapt2 已验证权限与 provider 均打进包。
- 本地打包通过：`build/app/outputs/flutter-apk/app-release.apk`（arm64，302.6MB）。
- CI 工作流改为双端出包：同一提交数 N 构建 Windows zip + Android arm64 APK，两个资产一起上传 `latest` Release（元数据 versionCode 共用）。
- 本日此前两件事（均已推送并 CI 过）：LLM 渠道去默认百炼+槽位化、语音识别收敛纯本地（364 用例）；安卓 APK 首次打包交付。

## 未完成项与下一步

- **老板一次性手动安装**：现装安卓包 versionCode=1 且无自更新逻辑，需手动装一次 CI 出的新 APK（推送后 Release 上 `peixi-android-arm64.apk`，versionCode≈90）；此后安卓即可应用内更新。
- 安卓实机验收链路：点更新 → （首次）跳「安装未知应用」授权页 → 允许 → 回来再点「安装」 → 系统安装器完成升级。
- Windows 端 GUI 更新链路实机点击验收（更早遗留）。
