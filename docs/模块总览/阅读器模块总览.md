# 阅读器模块总览

> 最后更新：2026-10-26（v6 阅读体验升级：章尾接续/进度/沉浸/常亮/搜索/书签/卷分组目录）

## 模块职责（一句话）

小说正文阅读页：纵向滚动看书 + AI 批注（L1~L4）随到随显 + 微信读书级阅读体验（进度、沉浸、搜索、书签、屏幕常亮）。

## 运作流程（从打开到合上书）

### 1. 进入

媒体库书架卡片点「开始阅读」→ `libraryEntryGate`（`lib/features/library/library_page.dart`）：小说项目只要不是「处理失败」就直接进 `ReaderPage`（导入即可读，不必等 AI 批注跑完）。

### 2. 初始化（ReaderPage.initState）

`lib/features/reader/reader_page.dart`：

1. 开屏幕常亮（`WakelockPlus.enable()`，退出阅读页 disable 恢复系统设置）；
2. 读阅读偏好（字号/行距/背景/页边距，存 settings 表，键 `reader.*`）；
3. 读全书章列表（chapters 表按 idx 升序）；末章 endPara+1 = 全书总段数（进度折算用）；
4. 读 `projects.meta_json` 的 `reading` 键（上次读到第几章+滚动偏移+全书百分比），有记录就恢复到那个位置。

### 3. 看书（每章一个 ListView）

- 正文按段落渲染（`_paragraphItem`）：段落文字 → 批注气泡（L1 潜台词/L2 心理/L3 知识，点击弹底部卡）→ L4 思考题段间卡片（作答/跳过写 qa_records）。批注是管线后台跑的，通过防抖（800ms，maxWait 2s）随到随显，不重查正文。
- **滚动即更新进度**：ScrollUpdate 通知 → `_updateProgress` 算本章%（offset/maxScrollExtent，一屏章恒 100%）与全书%（章起点 startPara + 章内插值 × 章段数，除以全书总段数），写进 ValueNotifier——底部信息条局部刷新，不重建整页。滚动停止（ScrollEnd）时把位置持久化回 meta_json（chapterIdx + scrollOffset + progressPercent，书架卡片「已读 x%」直接读最后一个值）。
- **章尾接续**：列表末尾多一项——有下一章显示「下一章 · 标题」按钮，一键开下一章；末章显示「已是最后一章」。
- **沉浸模式**：点正文任意处切换顶/底栏收起（200ms 高度动画 + Visibility 不留 element + OverflowBox 恒定内容高防过渡帧布局溢出）；安卓同步切系统沉浸式状态栏。批注气泡/L4 卡片的点击在子级先命中，不会被误触成沉浸切换。
- **全书搜索**：顶栏放大镜 → 弹层输入（防抖 400ms）→ `ReaderRepository.searchParagraphs`（SQLite LIKE，按全书段落序号升序，上限 200 条）→ 结果带章名+命中片段高亮 → 点击 `_jumpToPara`：按段落全局序号定位所属章（startPara≤idx≤endPara），开章后用 GlobalObjectKey('para-<id>') ensureVisible 滚到命中段。
- **书签**：长按正文段落 → 加书签（可选一句备注）或移除已有。数据在 bookmarks 表（v6 新增，段落删除级联清理）。目录抽屉有「章节/书签」两个页签，书签新→旧（createdAt 相同毫秒时按自增 id 兜底），点条目直达段落。

### 4. 目录抽屉

左侧抽屉：按卷分组（chapters.volume 变化处插卷头，无卷书平铺）；当前章高亮并自动滚到可见（偏上 1/3）；「上次读到」Chip 快跳。

## 入口文件

- `lib/features/reader/reader_page.dart` — 阅读页全部 UI 与交互
- `lib/features/reader/reader.dart` — ReaderRepository（章/段/批注/进度/搜索/书签数据层）+ 批注 JSON 解码（decodeL1L2/L3/L4）
- `lib/core/settings/app_prefs.dart` — ReaderPrefs（字号/行距/ReaderTheme 三主题/ReaderMargin 三档边距）
- `lib/core/settings/settings_repository.dart` — 偏好持久化（settings 表）

## 对外接口 / 被谁调用

- `ReaderPage(projectId)`：被媒体库 `libraryEntryGate` 调用（唯一入口）
- 阅读进度写回 projects.meta_json 的 `reading` 键（与 ProjectMeta/NovelMeta 两个视图共存，互不覆盖）

## 依赖的上游模块

- 数据库（AppDatabase v6：chapters.volume、bookmarks 表）
- 处理管线（pipelineControllerProvider——只读批注进度事件做随到随显）
- 设置存储（SettingsRepository——阅读偏好）
- 小说导入解析（chapters/paragraphs 的生产方）

## 关键数据结构

- `ReaderPrefs{fontSize, lineHeight, theme, margin}` — 三主题色值硬编码在 ReaderPage（paper/sepia/night，既有持久化语义，不随全局主题变）
- `ReadingProgress{chapterIdx, scrollOffset, progressPercent?}` — meta_json.reading 视图
- `SearchHit{paraId, paraIdx, content, chapterTitle?}` / `BookmarkHit{id, paraId, paraIdx, chapterId?, paraContent, note?, chapterTitle?}` — 搜索/书签查询产物

## 已知坑与约束

- **自绘顶/底栏而非 AppBar**：沉浸切换需要高度动画（AnimatedContainer 0↔kToolbarHeight），Scaffold.appBar 做不了。代价：状态栏图标色要自己用 AnnotatedRegion 设（浅色书页用深色图标）。
- **沉浸还原动画的过渡帧**：容器高度小于内容固定高时会触发布局溢出——内容必须包 OverflowBox 恒定高度（20-17=3px 的教训，测试锁着）。
- **弹层 TextEditingController 不能在 whenComplete 里 dispose**：弹层退出动画期间 TextField 仍引用 controller，立即 dispose 报 used-after-disposed；弹层关闭后无引用，交给 GC。
- **搜索是 LIKE 全表扫描**：几十 MB 大书在手机上可能秒级，弹层有 loading 态 + 结果上限 200 条兜底；关键词含 % 或 _ 时匹配会偏宽（drift 的 like 不支持 escape 参数），仅影响结果宽窄无数据风险。
- **划线高亮没做**：与 L1~L4 批注气泡视觉冲突，回看需求由书签覆盖（老板已确认全家桶范围如此取舍）。
- 大书目录抽屉用 ListView.builder 惰性构建（章+卷头扁平行表），几千章不卡。
