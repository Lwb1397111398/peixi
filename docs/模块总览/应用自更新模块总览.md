# 应用自更新模块总览

## 模块职责

一句话：让「陪析」自己发现新版本、下载安装包并完成安装（Windows 替换重启 / Android 交系统安装器）；配合 GitHub Actions 云端出包，人只管推代码。

## 运作流程

按数据真实流动顺序走一遍（以 Windows 桌面端为例）：

1. **云端出包（CI，不是 App）**：每次 push 到 `main`，GitHub Actions 工作流 `.github/workflows/build-release.yml` 被触发。它在 windows-latest 机器上：全量 checkout（`fetch-depth: 0`）→ 装 Flutter 3.47.1 → `flutter analyze` + `flutter test` 两个关卡 → 跑 `tool/fetch-windows-native-deps.sh` 预取 ffmpeg-kit/libmpv/ANGLE 三个原生包（CI 直连不走镜像）→ 用 `git rev-list --count HEAD` 算出提交数 N，执行 `flutter build windows --release --build-name=0.1.$N --build-number=$N` → 把 `build/windows/x64/runner/Release/` 全部内容压成 `dist/peixi-windows-x64.zip` → 同一提交数 N 再执行 `flutter build apk --release --target-platform android-arm64 --build-name=0.1.$N --build-number=$N` 产出 `dist/peixi-android-arm64.apk` → 用 `gh release` 把 zip+apk 两个资产覆盖上传到仓库唯一的 `latest` Release，Release 说明第一行是元数据注释 `<!-- appupdate versionCode=N versionName=0.1.N -->`，后面跟最近 5 条提交标题。仓库永远是"最新版"一个入口，App 不用解析多版本。
2. **检查更新（App 内）**：启动后 5 秒（`lib/ui/app_shell.dart` 的 `_silentUpdateCheck`）或用户在设置页点「检查更新」（`lib/features/settings/update_section.dart`），`UpdateService.check()` 匿名 GET `https://api.github.com/repos/Lwb1397111398/peixi/releases/latest`（公开仓库零令牌；必须带 `User-Agent` 头，GitHub 强制）。纯解析逻辑在 `lib/core/update/update_checker.dart`：正则 `parseUpdateMetadata` 从说明第一行抓 versionCode/versionName；`parseLatestReleaseJson` 在 assets 里按平台挑资产（Windows `.zip` / Android `.apk`，`assetExtensionFor` 决定）拿下载地址与字节数；两端共用同一元数据 versionCode；`isNewer` 拿远端 versionCode 与本地构建号（`package_info_plus` 读 exe 内嵌 buildNumber）比较，更大才算有更新。
3. **节流与开关**：静默检查受 24 小时节流（`shouldAutoCheck`，上次检查时间存 settings 表 `update.last_check_ms`）；用户可在设置页关掉自动检查（`update.auto_check`）。失败保持静默不打扰，手动检查则弹完整人话报错（403=限流、404=还没发过版、网络不通）。
4. **下载（App 内）**：`UpdateService.download()` 把 zip 流式下到 `<系统临时目录>/peixi_update/update-<versionCode>.zip`。三层保护：① 同版本完整文件已存在直接复用不重下；② 半截包保留为 `.part`，下次带 `Range: bytes=已收-` 断点续传；③ 国内直连 `release-assets.githubusercontent.com` 常被整段阻断 → 失败后按序换镜像前缀重试（2026-10-25 实测存活：`https://ghfast.top/`、`https://gh-proxy.com/`；只对 `https://github.com/` 开头的地址拼镜像）。单源 30 秒读超时快速判死，下载完校验字节数与元数据 size 一致才改名正式文件。
5. **安装（App 内）**：Android 走 `applyUpdate()` 的安卓分支——MethodChannel `peixi/app_update` 调 MainActivity 的 `installApk`：未授予「安装未知应用」时先跳系统设置授权页（返回 need_permission，弹窗提示回来再点一次安装），已授权则 FileProvider 把 `<cache>/peixi_update/` 里的 APK 交给系统安装器，本进程不退出。Windows 用 archive 包的 `extractFileToDisk` 把 zip 解压到 `<临时目录>/peixi_update/new-<versionCode>/`，生成纯 ASCII 的替换批处理（`buildUpdateBatScript`）并以分离进程执行 `cmd /d /c apply_update.bat <安装目录> <新文件目录> peixi.exe`。批处理用 `tasklist` 最多等 120 秒让本程序退出 → `robocopy /MIR` 把新文件整个覆盖到安装目录 → `start` 重启 peixi.exe。弹窗随后 `exit(0)`。用户数据（drift 数据库、音频、导入的媒体）都在 `getApplicationSupportDirectory`/`getApplicationDocumentsDirectory`，不在安装目录，替换不碰它们。

## 入口文件清单

- `lib/core/update/update_checker.dart` — 纯解析/比较/节流/镜像拼接（无 IO，可单测）
- `lib/core/update/update_service.dart` — 检查/下载/续传/镜像兜底/解压/替换重启的编排
- `lib/features/settings/update_section.dart` — 设置页「应用更新」分区
- `lib/features/settings/update_dialog.dart` — 更新弹窗（确认→下载进度→安装并重启）
- `lib/ui/app_shell.dart` — 启动静默检查挂载点（`_silentUpdateCheck`）
- `lib/core/settings/settings_repository.dart` — `update.last_check_ms` / `update.auto_check` 两个键
- `lib/providers.dart` — `updateServiceProvider`
- `.github/workflows/build-release.yml` — CI 出包与发版
- `tool/fetch-windows-native-deps.sh` — 原生依赖预取（CI 时镜像列表置空直连）
- `test/update_test.dart` — 22 个单测（解析/比较/镜像/节流/假服务器下载续传/批处理脚本）

## 对外接口 / 被谁调用

- `UpdateService`：`check()`、`download()`、`applyUpdate()`、`packageInfo()`、`localVersionCode()`；被 AppShell（启动静默）与设置页（手动检查）调用。
- `showUpdateDialog(context, ref, info, currentVersionCode)`：两处检查入口共用的弹窗。
- 对外网络面：GitHub Releases API（api.github.com，匿名）与 Release 资产下载（含镜像前缀）。

## 依赖的上游模块

- `core/settings`（SettingsRepository 存节流时间戳与开关）
- `providers.dart`（dio、settingsRepo 等注入）
- 主题 token（Space / SemanticColors，弹窗与分区样式）

## 关键数据结构

- **版本号约定**：versionCode = git 提交数（CI 算出注入 exe；本机同提交算出同号），versionName = `0.1.<提交数>`；比较只看 versionCode。
- **Release 元数据**：`latest` Release 说明第一行 `<!-- appupdate versionCode=N versionName=0.1.N -->`；资产固定名 `peixi-windows-x64.zip`。
- **落盘布局**：`<临时目录>/peixi_update/update-<versionCode>.<zip|apk>`（成品，扩展名随平台）、`.part`（断点）；Windows 另有 `new-<versionCode>/`（解压产物）与 `apply_update.bat`（替换脚本）。
- **Android 安装授权**：`REQUEST_INSTALL_PACKAGES` 权限 + `androidx.core.content.FileProvider`（authorities `com.jingyue.peixi.fileprovider`，路径白名单 `res/xml/file_paths.xml` 只放行 `peixi_update/`）；未授权时 MainActivity 跳 `ACTION_MANAGE_UNKNOWN_APP_SOURCES`，Dart 侧收 need_permission 抛人话提示。

## 已知坑与约束

- **批处理必须纯 ASCII**：cmd 按 GBK 解析 bat，中文注释会乱码出错；路径经命令行参数（Unicode 安全）以 `%~1` 传入，不写进文件。
- **替换期间会闪一个黑色 cmd 窗口**几秒钟（等退出+robocopy），属预期行为；个人自用可接受。
- **测试环境不能留 Timer**：AppShell 的 5 秒静默检查用 `Platform.environment['FLUTTER_TEST']` 守卫，否则 fake_async 不变式炸测试。
- **首次带镜像兜底的版本自身装不上**（旧版没有兜底逻辑时直连下不动）：逃逸路径是浏览器开镜像链接手动下载覆盖安装（镜像域名国内可达）；装上第一个带兜底的版本后即全自动。
- **镜像站死得快**：发版前用 `curl -sL -r 0-1023 -m 15 -o /dev/null -w "%{http_code} %{size_download}B" "<镜像>/<资产URL>"` 逐个判活，回 `206 1024B` 即活；死一个删一个（改 `UpdateService.mirrors` 默认值）。
- **Android 一次性升级**：2026-10-25 之前装的安卓包（versionCode=1）没有自更新逻辑，需手动装一次 CI 出的新 APK；之后即可应用内更新。
- **安卓安装取消不回到弹窗**：系统安装器接管后用户「取消」只回到桌面/本应用，弹窗停留在「已交给系统安装器」提示，再点「安装」可重来（APK 已缓存不重下）。
