## 二、使用步骤

1. 设置页填 API 配置（默认百炼 compatible-mode + API Key）与 OSS 中转桶（bucket/endpoint/AK/SK）。
2. 媒体库 → 导入视频 → 自动跑 S1-S6，停在"待校准"。
3. 点卡片进校准页：试听每个声音簇、确认/改名 → 确认后自动完成 S8-S10。
4. 状态"可观看"后点卡片进播放器；L4 到点自动暂停提问，答完继续。

## 三、偏离设计稿的决策（原因）

1. **OSS 自实现而非 dart_aliyun_oss**：V1 签名纯本地可单测（hmac-sha1，测试离线复算签名比对）；无未验证三方依赖。
2. **上传单次 PUT 而非分片**：单集 16kHz/48kbps 音频约 20MB，无分片必要；进度条走 onSendProgress。
3. **试听用 media_kit AudioPlayer**：省 just_audio(_windows) 依赖，播放器与校准页共用一套引擎。
4. **抽音频格式运行时探测**（libmp3lame→mp3，aac→m4a，wav 兜底）：规避 ffmpeg-kit 变体裁剪风险；Windows 实测 full-gpl 含 libmp3lame。
5. **Android 导入时复制视频进应用目录**：SAF 缓存路径不可长期依赖；Windows 直接引用原路径。
6. **S2 字幕提取后仅解析入库 metaJson**：与 ASR 交叉校对、角色名提升属于调优期功能，不阻塞 M1。
7. **minGapMinutes 按播放位置差**（非墙钟）：拖进度条不受惩罚，符合"观看节奏"语义。
8. **L4 只在 importance=high 且有问题的场景触发**（设计稿 8.2 原文如此）。
9. **ASR file_urls 用 Uri.encodeFull 包裹签名 URL**：与早前真机核对的请求一致（spec §3.1）。
