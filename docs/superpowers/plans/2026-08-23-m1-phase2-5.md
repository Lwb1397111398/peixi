# 陪析 M1 Phase 2-5 实施计划（视频管线 → 校准 → 播放器 → Android 适配）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 M1 视频主链路全部剩余工作：S1-S10 管线（可断点续跑）、S7 校准闸门、播放器（解说卡随场景切换 + L4 弹幕提问打断）、Android 适配，双端构建通过。

**Architecture:** 所有外部 IO（ffmpeg/OSS/ASR/LLM）抽象为可注入接口，dio 类用 FakeAdapter 离线单测；`PipelineEngine` 以 projects.status 为唯一事实源逐阶段推进（每阶段落盘，崩溃可续跑）；Riverpod `PipelineController` 管理后台运行与进度广播。UI 按 8.2/8.3 规格。

**Tech Stack:** 既有 drift/dio/riverpod + 新增 media_kit(视频+试听)、ffmpeg_kit_flutter_new、file_picker、wakelock_plus、crypto(OSS V1 签名自实现，替代 dart_aliyun_oss——签名纯本地可单测、无未验证三方依赖)。

**关键决策（偏离设计稿处，交付说明须注明）：**
1. OSS 上传用单次 PUT + onSendProgress（单集音频 ~20MB，无需分片）；签名/签名URL 自实现（crypto hmac-sha1）。
2. 试听用 media_kit AudioPlayer（省 just_audio_windows 依赖）。
3. 抽音频格式探测：按 [libmp3lame→mp3, aac→m4a] 运行时探测可用编码器，规避 ffmpeg-kit 变体裁剪风险。
4. Android 导入时将视频复制进应用目录（SAF 路径 ffmpeg/播放器不可直接读）；Windows 直接引用原路径。
5. S2 字幕提取后仅解析入库 metaJson（交叉校对/角色名提升为调优期功能，不阻塞 M1）。
6. minGapMinutes 按播放位置差（非墙钟）计算。
7. 本地 ASR（sherpa_onnx 双模式）为 T20 加演任务，云端为默认且唯一完整实现。

### Task 3: ffmpeg 门面 `lib/core/media/ffmpeg_service.dart`
```dart
class MediaInfo { final int durationMs; final bool hasSubtitle; final String? subtitleCodec; }
abstract class FFmpegService {
  Future<MediaInfo> probe(String path);
  Future<void> extractAudio(String input, String output, {void Function(double)? onProgress}); // -vn -ac 1 -ar 16000 -b:a 48k，格式按探测
  Future<String?> extractSubtitle(String input, String outputSrt); // 无流返回 null，异常吞掉（S2 不阻塞）
  Future<List<String>> availableAudioEncoders(); // -hide_banner -encoders
}
class FFmpegKitService implements FFmpegService   // 真实现：FFprobeKit / FFmpegKit.executeAsync + statistics.time/1000÷duration
class FakeFFmpegService implements FFmpegService  // 测试用
```
probe 解析 FFprobeKit.getMediaInformationJson：duration(ms 毫秒字段 `duration`*1000)、streams[].type=='subtitle'。
extractAudio 进度：session.statistics.time (ms) / durationMs。编码器选择缓存在内存。

### Task 6: 管线引擎 `lib/features/pipeline/pipeline_engine.dart`
```dart
enum ProjectStatus { imported, audioReady, uploaded, asrDone, mapped, waitCalibration,
  calibrated, segmented, commentaryDone, ready, failed, asrRunning /* 内部瞬态不入库? → 入库用 metaJson.asr_task_id + status=audioReady 重入 */ }
class PipelineEvent { int projectId; String stage; double? progress; String? detail; ProjectStatus status; }
class PipelineEngine {
  PipelineEngine({required db, required ffmpeg, required oss, required asr, required llm, required settings, required audioDir});
  Stream<PipelineEvent> get events;   // broadcast
  Future<void> run(int projectId);    // 从当前 status 推进到 WAIT_CALIBRATION / READY / FAILED
  Future<void> confirmCalibration(int projectId, Map<int,String> charIdToName); // S7 → status=calibrated → run()
  Future<void> retry(int projectId);  // FAILED → failedStage 重跑
}
```
- 阶段表：imported→[subtitle(S2,可跳过)]→audio(S3)→audioReady→upload(S4, meta: oss_key/url)→asr submit(S5, meta: asr_task_id, status→uploaded 保持+meta.running?)。**断点策略**：ASR 提交后 status 仍=uploaded、metaJson.asr_task_id 存在则 poll 续跑（app 被杀重启场景）；poll 成功→写 segments 全量行（idx 连续、speaker_char_id 空）+status=asrDone；随即删 OSS 对象。mapped(S6)→waitCalibration→[闸门]→calibrated→segmented(S8)→commentaryDone(S9)→ready(S10: keepTempAudio=false 时删音频文件)。
- 任一阶段抛错：status=failed+failed_stage=阶段名，event 广播；retry 从 failed_stage 重入（各阶段入口幂等：音频文件存在则跳过等）。
- metaJson 助手类 `ProjectMeta`（json 编解码：ossKey/ossUrl/asrTaskId/episode/durationMs/subtitle[]/audioFormat）。
- 测试：全 fake 走通 imported→waitCalibration→confirm→ready；中途抛网络错→failed+failed_stage=upload→retry 成功；模拟杀进程（新建 engine）在 asr poll 续跑；ASR 完成后 OSS 对象被删。

### Task 10: 场景切分 `lib/features/pipeline/scene_segmenter.dart`
`List<SceneSlice> segment(List<SegmentRow> segs)` 纯函数：
1. 相邻对白 end→next.start 间隔 >3000ms 切；
2. 切完单场景时长 >120000ms 在内部最大间隔处再切（无间隔则 120s 硬切）；
3. <15000ms 的场景并入时长较小的邻景（无邻景则保留）；
4. 输出 idx 连续、startMs=首段 start、endMs=末段 end。
- 测试：常规切分/超长内部切/硬切/短景并入/单场景/空输入。
